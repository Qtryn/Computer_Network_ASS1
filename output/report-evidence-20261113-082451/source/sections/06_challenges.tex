\section{Challenges and Solutions}

\noindent\textbf{1. UDP reliability after retry exhaustion.}\quad
UDP neither acknowledges packets nor guarantees ordering. A lost early packet can block later frames in the same ordered stream. The transport therefore uses sequence numbers, per-stream buffering, a four-packet send window and timeout-based retransmission. Crucially, when a send exhausts its retries, the next attempt retransmits the \emph{same outstanding frames} with unchanged UUIDs and sequences, rather than skipping the missing sequence or resetting one side. Loss/reordering and recovery tests exercised this case.

\medskip\noindent\textbf{2. Avoiding false delivery and duplicate chat.}\quad
An ACK from the server only proves transport acceptance at one hop. A recipient might disconnect before it processes a forwarded message. We added stable message IDs, recipient-level \texttt{CHAT\_ACK} and sender-facing \texttt{CHAT\_RECEIPT}. A bounded per-account RAM outbox retries uncertain messages, while sender/ID de-duplication prevents repeated display. Restart, lost-ACK, changed-content UUID and account-isolation tests validate these rules. This is not durable exactly-once delivery across application restarts.

\medskip\noindent\textbf{3. Keeping chat responsive during large file transfers.}\quad
If chat and file chunks shared a single ordered stream, file traffic could delay interactive messages. Each file therefore has its own stream UUID, while chat uses a session-derived stream. The browser also initially rebuilt the recipient list on every poll and allowed thousands of progress events to evict chat events. Updates now preserve the selected recipient and retain only the latest progress per transfer. Chrome verification showed chat appearing during a 2-MiB transfer.

\medskip\noindent\textbf{4. Safe cleanup after interrupted transfers.}\quad
Partial files and server relay entries can remain if one peer exits unexpectedly. The receiver writes to a temporary \texttt{.part} file and exposes the final destination only after size/index and SHA-256 checks succeed. Disconnects or 60-second inactivity trigger transfer abort/cleanup; verified files are preserved. Regression tests check file metadata, temporary files, sockets and worker threads after concurrent transfers and logout.

\medskip\noindent\textbf{Engineering lesson.}\quad
The most important distinction was between \emph{transport delivery}, \emph{application acceptance}, and \emph{verified file integrity}. Expressing these as separate protocol events made errors observable and kept the design small enough to test. Fixed-window flow limiting remains deliberately distinct from BBR/CUBIC congestion control.
