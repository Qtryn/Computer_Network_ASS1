\section{Limitations and Conclusion}

The implemented collaboration application uses raw TCP/TLS control sockets and encrypted UDP DATA packets for broadcast/private chat and reliable file transfer. The packet format, sequencing, acknowledgments, retransmission and SHA-256 file verification are implemented explicitly. The final audit records 65 passing Python tests, a 20-client localhost load run, trusted HTTPS browser workflows, and an actual Wireshark/Npcap retransmission trace.

The current scope has clear limits: the outbox exists only while the local client process runs; no offline message composition, file resume, durable chat history, adaptive congestion window, BBR or CUBIC is implemented. The application uses a shared AES-GCM key for UDP hops rather than end-to-end encryption and has not been tested on two independent LAN hosts. These limitations should be considered when interpreting the results. Within the recorded localhost scope, the work demonstrates the core custom-protocol, concurrency, security and recovery concepts required by Assignment 1.
